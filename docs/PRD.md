# 钢铁现货仓库 · 驾驶员提货导航 产品需求文档（PRD）

> 项目代号：InvMap（仓库导图）
> 文档版本：v1.0
> 适用客户：钢铁现货仓储企业（厂区多库、库内库位管理）
> 文档作者：产品

---

## 1. 背景与问题

钢铁现货仓库通常占地大、库房多（1～N 号库）、库内以"区-排-位"方式管理大量库位。提货驾驶员到达厂区后普遍面临以下问题：

1. **不知道自己要提哪些货**：一个司机一趟可能要提多张提单，分布在不同仓库、不同库位。
2. **找不到库/找不到库位**：厂区道路复杂，库房编号不直观，库内库位更难定位，反复问人、绕路。
3. **提货顺序不合理**：随机进库导致重复绕行、园区拥堵、装车等待时间长。
4. **纸质单据流转慢**：提货单需要到办公室排队领取、人工核对手机号与提单。

最终结果是：**单车在场时间长、园区周转效率低、客服/调度人力投入大、司机体验差**。

## 2. 产品目标

为提货驾驶员提供一个"**到办公室即可自助查询 + 厂区 3D 导航 + 一键打印提货单**"的工具，做到：

- 司机**录入手机号**即可看到名下**全部待提提单**及其**仓库 + 库位**。
- 在**仓库 3D 图**上直观看到每张提单库位位置（默认全部展示，可点击单张高亮为红色）。
- 自动给出**最优提货顺序**与**行车路线**（从大门进 → 依次到各提货仓库 → 出门），让司机清楚"先去哪、再去哪"。
- 支持**一键打印提货单**。
- 提单数据**来源于 ERP**，通过 API 实时获取，库位信息精确到库位号。

### 2.1 衡量指标（北极星 & 辅助指标）

| 指标 | 说明 | 目标 |
| --- | --- | --- |
| 单车在场时长 | 进门到出门平均耗时 | 下降 ≥ 25% |
| 自助查询率 | 通过本产品查询提单的司机占比 | ≥ 80% |
| 客服问询量 | "我的货在哪/提单在哪"类咨询 | 下降 ≥ 50% |
| 一次找对率 | 司机按导航一次找到库位的比例 | ≥ 90% |
| 提货单自助打印率 | 自助打印占总提货单比例 | ≥ 70% |

## 3. 用户与场景

### 3.1 角色

- **提货驾驶员（主角）**：年龄跨度大、对复杂操作不敏感、单手操作、嘈杂强光环境（厂区/驾驶室）。
- **仓库调度/客服**：维护库区库位基础数据、处理异常提单、辅助司机。
- **门岗/磅房**：核验提货单、放行。
- **系统管理员**：维护厂区 3D 模型、库位坐标映射、ERP 对接配置。

### 3.2 核心场景（Happy Path）

1. 司机到办公室，打开自助终端（或扫码进入手机端 H5）。
2. 输入手机号 → 获取验证码（可选）→ 进入"我的提货"页面。
3. 页面顶部显示：**共 N 张提单 / 涉及 M 个仓库 / 合计 X 吨**。
4. 列表逐条显示提单：货物、规格、重量/件数、**仓库 + 库位**、状态。
5. 3D 图默认展示全部提单库位（不同提单不同颜色 + 编号）。
6. 系统给出推荐提货顺序：① 3 号库 → ② 1 号库 → ③ 5 号库，并在 3D 图上画出行车路线（大门进 → 各库 → 出门）。
7. 司机点击某张提单 → 该库位在 3D 图上高亮为**红色**并镜头聚焦、其余弱化；面板显示该库位的进库门、所在区排位。
8. 司机点击"打印提货单" → 打印该单（或全部）。
9. 司机按顺序逐库提货，每提完一张可在列表标记/系统自动随 ERP 状态刷新。

### 3.3 异常场景

- 手机号查不到提单：提示"未查询到名下提单，请联系客服 / 核对预约手机号"。
- 提单被冻结/欠费/未审核：列表中置灰，标注原因，不计入路线。
- 库位临时变更（移库）：以 ERP 最新库位为准，3D 实时刷新并提示"库位已更新"。
- 网络/ERP 异常：展示缓存数据 + 明显的"数据可能不是最新"提示，提供重试。
- 同一手机号多货主/多车：支持按车牌或提单分组筛选。

## 6. 关键功能详细设计

### 6.1 登录 / 手机号录入

- 大号数字键盘（适配终端触屏），手机号 11 位校验。
- 验证码可由后台配置是否开启（自助终端可关闭以提效，H5 建议开启）。
- 登录态：会话级（终端不长期保存司机信息，保护隐私；H5 可记住本机）。

### 6.2 提单列表

每条提单字段（来源 ERP）：

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 提单号 | TD20260531001 | 唯一标识 |
| 货主/客户 | 某某钢贸 | |
| 货物名称 | 螺纹钢 HRB400E | |
| 规格 | Φ20 9m | |
| 重量 | 26.5 吨 | |
| 件数/捆数 | 5 捆 | |
| 仓库 | 3 号库 | warehouseId 映射 3D 模型 |
| 库位 | C 区-07 排-03 位（C-07-03） | 精确到库位 |
| 状态 | 待提货 / 部分提货 / 已提货 / 冻结 | |
| 提货码 | 8821 | 门岗/库管核验 |

交互：

- 点击某条 → 选中并在 3D 高亮红色、镜头聚焦、显示详情。
- 复选框 → 选择要打印的提单。
- 顶部"全部展示"→ 取消单选，所有库位同时展示（不同颜色 + 顺序编号）。

### 6.3 3D 厂区导航（核心）

- **场景元素**：地面、园区道路、大门（含磅房）、各号库房（带顶、带编号牌）、库内库位网格、出入口。
- **库位定位**：ERP 库位编码 → 3D 坐标的映射表（库位坐标管理在后台维护，见 §8）。
- **默认态**：展示该司机全部提单库位，每个库位用立柱/光标 + 提单编号气泡标注，颜色按提货顺序区分。
- **选中态**：被选提单库位变**红色**并放大闪烁，镜头平滑聚焦到该库；其它库位降低透明度。
- **路线绘制**：从大门起点出发，按推荐顺序连接各提货库房入口，最终到出门口，用带箭头的路径线表示行进方向，并在每个库房入口标注序号 ①②③。
- **视角控制**：可旋转、缩放、平移；提供"重置视角""俯视全景""跟随选中"按钮。
- **可达性**：颜色不只用红绿区分（考虑色盲），叠加序号与图标。

### 6.4 提货顺序 / 路线规划

- 输入：大门坐标（起点）、各提货库房入口坐标、出门坐标（终点）。
- 算法（MVP）：以厂区道路图为基础的**最近邻 + 局部优化**的路径排序（开放式 TSP 近似），目标最小化总行车距离/时间。
- 约束（可扩展）：单行道、限高限重、危化分区、装卸区拥堵权重。
- 输出：有序库房列表 + 每段路线几何 + 预计距离/时长。
- 兜底：若道路图不完整，退化为按库房欧氏距离排序。

### 6.5 打印提货单

- 打印内容：提单号、货主、货物/规格/数量、仓库 + 库位、提货码、二维码（供门岗扫码核销）、打印时间。
- 支持"打印选中""打印全部"。
- 终端走小票/A4 打印机；H5 走系统打印（`window.print()` + 专用打印样式）。
- 打印模板与屏幕展示分离，避免把 3D/导航元素打进单据。

## 7. 数据来源与 ERP 接口对接

提单数据全部来自 ERP，导航系统**只读**。详细接口契约见 [`API.md`](./API.md)。核心接口：

1. `GET /api/pickup/orders?phone=` 按手机号查询待提提单（含仓库、库位编码）。
2. `GET /api/warehouses` 厂区与库房基础信息（用于 3D 模型与坐标映射）。
3. `POST /api/pickup/print-log`（可选）打印/核销日志回写。

库位编码与 3D 坐标的映射，由 InvMap 后台维护（ERP 提供库位编码，InvMap 维护坐标），保证 ERP 不需要关心 3D。

## 8. 后台 / 基础数据管理

- **厂区与库房建模**：上传/编辑园区平面、库房尺寸位置、道路、出入口。
- **库位坐标映射**：库位编码（区-排-位）↔ 3D 坐标，支持批量导入（Excel）。
- **ERP 对接配置**：接口地址、鉴权、字段映射、轮询/Webhook。
- **运营配置**：是否开启验证码、打印模板、路线算法参数（道路权重）。

## 10. 验收标准（MVP）

1. 输入存在提单的手机号，能在 1.5s 内返回全部待提提单且字段完整（含库位号）。
2. 3D 图默认展示全部库位；点击某提单该库位变红并聚焦，"全部展示"可还原。
3. 系统给出提货顺序并在 3D 图上画出"大门→各库→出门"的带箭头路线。
4. 打印的提货单包含提单关键信息与核销二维码，且不含导航/3D 元素。
5. 异常手机号、冻结提单、ERP 故障均有明确提示与兜底。

## 11. 里程碑（按交付物，不按工期）

1. 数据契约对齐（ERP 接口字段、库位编码规则）。
2. 后台库位坐标映射 + 厂区/库房 3D 基础模型。
3. 前端：登录 → 列表 → 3D 导航 → 路线 → 打印 闭环。
4. 联调 ERP 真实接口、灰度一个厂区、收集指标迭代。

## 附录 A：数据模型修订（提单含多商品明细）

实际业务中**一张提单可能包含多个商品，且每个商品可能在不同仓库、不同库位**。因此数据模型为：

- 提单 bill：`billNo`、货主、提货码、整体状态、`items[]`
- 明细 item：货物、规格、数量、`warehouseId`、`locationCode`（区-排-位）、状态

对应到产品交互：

- **提单列表**展开显示每条商品明细及其"仓库 + 库位"；明细前的 ①②③ 表示其仓库在推荐路线中的提货顺序。
- **总览地图**为每条明细打库位标记；行车路线覆盖该司机**所有明细涉及的全部仓库**。
- **点击提单**：若其商品都在同一仓库 → 直接进入该库内并高亮全部目标库位；若跨多个仓库 → 在总览高亮全部库位并提示按路线依次提货。
- **点击单条商品**：进入其所在仓库的库内 3D 视图，精确高亮该库位。

接口契约见 `docs/API.md`（`orders[].items[]` 结构）。

## 附录 B：行车路线如何生成 / 配置

总览地图中的行车路线由系统**自动规划**，输入来自厂区配置，无需人工逐条绘制：

1. 输入：厂区**道路网络**（横/纵道路段）、各库房**入口坐标**、大门/出门坐标。
2. 建图：道路交叉点、库房入口、大门出门接入一张加权路网图（权重=路段距离）。
3. 排序：从大门出发，对"所有待提明细去重后的仓库集合"做最近邻排序（开放式 TSP 近似）得到提货顺序 ①②③…。
4. 求路径：相邻两站用 Dijkstra 求最短路并拼接，最后回到出门口。
5. 输出：有序仓库 + 带箭头路线几何 + 总里程，并在右侧步骤条联动展示。

**要调整路线**：在「仓库配置」中改道路网络或各库入口位置（或由后台/ERP 下发），路线自动重算。后续可把单行道、限高限重、装卸区拥堵等作为边权/约束扩展，得到更贴合现场的路径。

## 附录 C：库内布局为"灵活布局"（排数/每排库位数可不同）

库内并非规则网格。每个库房的**分区数、排数、以及每一排的库位数都可能不同**，同一库房内不同排的库位数也可能不同。模型：

```
warehouse.layout = [
  { "zone": "A", "rows": [8, 8, 6] },   // A区3排，库位数分别 8/8/6
  { "zone": "B", "rows": [10, 8] },     // B区2排，库位数 10/8
  { "zone": "C", "rows": [6, 6, 6, 6] } // C区4排，每排6
]
```

- `rows` 数组长度 = 该区排数；每个元素 = 该排的库位数。
- 3D 库内视图按此布局逐排、逐位渲染货架，并在每排标注"区-排（n位）"；总览图的库位标记与库内高亮均按该布局精确定位。
- 在「仓库配置」中，每个库房有一个「库内布局」编辑框，按 `区名: 各排库位数` 逐区填写即可（排数=逗号个数，每排库位数可不同）。未填写时回退到统一网格。
- 未提供 `layout` 时兼容回退到统一网格 `grid`（每排库位数相同）。
